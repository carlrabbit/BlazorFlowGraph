# Purpose

Define the repeatable process for finishing milestone execution without leaving durable guidance trapped in milestone notes.

# Preconditions

- milestone deliverables and exit criteria have been reviewed
- any remaining gaps or follow-up work have been identified

# Required Reading

- the target milestone document under `docs/milestones/`
- [`../SPECS.md`](../SPECS.md)
- [`documentation-review.md`](documentation-review.md)

# Execution Steps

1. Verify completed milestone outcomes against the milestone exit criteria.
2. Promote durable behavior into specs, architecture docs, decisions, or workflow docs as needed.
3. Remove or downgrade stale milestone-specific wording that implied lasting authority.
4. Record unfinished work as new milestone, bug, or spec follow-up items.
5. Update roadmap and index documents if milestone status changes.

# Validation

- durable outcomes live in the correct authority layer
- milestone status is discoverable
- roadmap and follow-up references are current

# Common Failures

- leaving permanent requirements only inside milestone notes
- marking a milestone finished without validating durable documentation
- losing follow-up work when closing the milestone

# Synchronization Requirements

- keep milestone closure aligned with specs, architecture docs, decisions, and roadmap documents
